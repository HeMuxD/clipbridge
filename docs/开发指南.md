# ClipBridge 开发指南

## 环境要求

| 组件 | 版本 | 说明 |
| --- | --- | --- |
| Go | 1.22+ | 服务端 |
| .NET SDK | 8.0+ | Windows 客户端 |
| Android Studio | Hedgehog+ | Android 客户端 |
| JDK | 17 | Android 构建 |
| Nginx | 1.20+ | 反向代理（生产） |

## 一、服务端

### 本地运行

```bash
cd server

# 首次运行会自动生成配置缺失项并使用默认值
cp config.example.yaml config.yaml
# 编辑 config.yaml：至少改 public_base_url

# 拉依赖（首次需要网络访问代理）
go mod tidy

# 运行
go run ./cmd/clipbridge -config config.yaml
```

> SQLite 驱动使用 `modernc.org/sqlite`（纯 Go 实现）而非 `mattn/go-sqlite3`，
> 目的是让 `CGO_ENABLED=0` 的静态编译与交叉编译都能正常工作。
> 详见 `go.mod` 文件内的说明。

启动后终端会打印配对码：

```
============================================================
                    配对码（首次配对使用）
                        482913
              有效至 2026-09-28 22:10:33
============================================================
```

配对码**一次性使用**，配对成功后立即作废。需要新的配对码时重启服务端，或：

```bash
go run ./cmd/clipbridge -config config.yaml -rotate-code
```

### 目录约定

运行时会创建：

```
server/
├── data/
│   ├── clipbridge.db      # SQLite 数据库
│   └── files/             # 上传的图片
└── config.yaml
```

### 常用参数

| 参数 | 说明 |
| --- | --- |
| `-config` | 配置文件路径，默认 `config.yaml` |
| `-version` | 打印版本号 |
| `-rotate-code` | 只生成新配对码后退出 |

### 构建与部署

```bash
# 交叉编译到 Linux amd64（纯 Go 驱动，无需 C 工具链）
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -ldflags="-s -w" -o clipbridge ./cmd/clipbridge

# 或者直接用构建脚本
./scripts/build.sh linux

# 上传到服务器
scp clipbridge config.yaml user@server:/opt/clipbridge/
scp -r migrations user@server:/opt/clipbridge/
```

服务器上：

```bash
sudo useradd -r -s /usr/sbin/nologin clipbridge
sudo mkdir -p /var/lib/clipbridge/files /etc/clipbridge
sudo chown -R clipbridge:clipbridge /var/lib/clipbridge
sudo chown -R clipbridge:clipbridge /opt/clipbridge

# 生成并写入 JWT 密钥，避免重启后所有设备需要重新配对
echo "CLIPBRIDGE_JWT_SECRET=$(openssl rand -hex 32)" | sudo tee /etc/clipbridge/env
sudo chmod 600 /etc/clipbridge/env

sudo cp deploy/systemd/clipbridge.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now clipbridge
sudo journalctl -u clipbridge -n 50 --no-pager     # 查看配对码
```

Nginx：

```bash
sudo cp deploy/nginx/clipbridge.conf /etc/nginx/sites-available/clipbridge
# 编辑：把 clip.example.com 换成你的域名
sudo ln -s /etc/nginx/sites-available/clipbridge /etc/nginx/sites-enabled/

# 签发证书
sudo certbot certonly --nginx -d clip.example.com

sudo nginx -t && sudo systemctl reload nginx
```

### Docker 部署（可选）

不想在服务器上装 Go 工具链与 Nginx 时，可以直接用容器跑服务端，配置在 `deploy/docker/`。

```bash
cd deploy/docker
cp .env.example .env
# 必填两项：
#   CLIPBRIDGE_JWT_SECRET       → openssl rand -hex 32
#   CLIPBRIDGE_PUBLIC_BASE_URL  → 对外访问地址
docker compose up -d --build
docker compose logs -f clipbridge    # 配对码打印在这里
```

镜像是多阶段构建：构建阶段用 `golang:1.22-alpine`，运行阶段是 `alpine:3.20` + 一个静态二进制
（纯 Go 的 SQLite 驱动让 `CGO_ENABLED=0` 成立）。数据库与图片放在命名卷 `clipbridge-data` 中，
容器重建不丢数据。

| 场景 | `CLIPBRIDGE_BIND` | 说明 |
| --- | --- | --- |
| 前置宿主机 Nginx | `127.0.0.1`（默认） | 容器只绑本机，由 Nginx 负责 TLS 与 WS 升级，最稳妥 |
| 直接暴露到局域网 | `0.0.0.0` | 明文 HTTP，Android 9+ 会拒绝，只适合 Windows 端或内网调试 |

两个容易踩的坑：

1. `deploy/docker/config.yaml` **不能删**。compose 会把它只读挂进容器；
   文件不存在时 Docker 会在宿主机上创建一个同名**目录**，容器启动随即失败。
2. 服务端自身已经能提供 `/f/` 图片下载，所以容器化时**不需要**让 Nginx 去读数据卷里的文件。
   `deploy/nginx/clipbridge.conf` 的 `/f/` 默认已改为反向代理；若你是 systemd + 固定路径部署，
   可以切回注释里的 `alias` 方案，性能更好（少一跳 Go 进程）。

## 二、Windows 客户端

```bash
cd clients/windows/src

# 调试运行
dotnet run

# 发布单文件 exe（用户无需安装 .NET 运行时）
dotnet publish -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true
```

产物位于 `bin/Release/net8.0-windows/win-x64/publish/ClipBridge.exe`，约 60~70 MB。

### 使用流程

1. 运行 `ClipBridge.exe`，自动弹出设置窗口；
2. 填入服务端地址（如 `https://clip.example.com`）；
3. 填入服务端日志中的配对码，点「配对 / 重新配对」；
4. 配对成功后关闭窗口，程序驻留托盘；
5. 在「设置」中按需勾选开机自启、排除的应用等。

### 关键实现说明

| 功能 | 实现 | 位置 |
| --- | --- | --- |
| 剪贴板监听 | `AddClipboardFormatListener` + `WM_CLIPBOARDUPDATE`，系统事件驱动，零轮询零权限 | `Interop/MessageWindow.cs` |
| 消息专用窗口 | `SetParent(hwnd, HWND_MESSAGE)`，窗口不可见、不占任务栏 | `Interop/MessageWindow.cs` |
| 截图目录监控 | `FileSystemWatcher` + 文件就绪检测（等待写入完成） | `Services/ScreenshotWatcher.cs` |
| 防回环 | `HashCache` 记录远端哈希，本地变更命中即跳过 | `Utils/Hashing.cs` + `Services/SyncOrchestrator.cs` |
| Token 存储 | DPAPI 用户级加密 | `Utils/SettingsStore.cs` |
| 开机自启 | `HKCU\...\Run` | `Utils/AutoStart.cs` |

## 三、Android 客户端

> ⚠️ **开发前必读**：Android 10+ 起，后台应用无法读取剪贴板，且**没有任何权限可以申请**。
> 详见 `docs/可行性报告.md` 第 3.2 节。客户端的架构必须围绕这一约束设计。

### 三种数据来源（按可靠性排序）

| 入口 | 可靠性 | 权限要求 | 说明 |
| --- | --- | --- | --- |
| **系统分享菜单** | ✅ 100% | 无 | 截图后点「分享 → ClipBridge」。**首推** |
| **通知栏一键复制** | ✅ 100% | 通知权限 | 接收下行内容的标准方式 |
| **无障碍服务** | ⚠️ 受厂商影响 | 无障碍授权 | 唯一免 Root 的自动上行方案 |

### 权限清单

```xml
<!-- 网络 -->
<uses-permission android:name="android.permission.INTERNET" />
<uses-permission android:name="android.permission.ACCESS_NETWORK_STATE" />

<!-- 前台服务（Android 14+ 必须声明具体类型） -->
<uses-permission android:name="android.permission.FOREGROUND_SERVICE" />
<uses-permission android:name="android.permission.FOREGROUND_SERVICE_DATA_SYNC" />
<uses-permission android:name="android.permission.FOREGROUND_SERVICE_MEDIA_PROJECTION" />

<!-- 通知（Android 13+ 运行时申请） -->
<uses-permission android:name="android.permission.POST_NOTIFICATIONS" />

<!-- 开机自启 -->
<uses-permission android:name="android.permission.RECEIVE_BOOT_COMPLETED" />

<!-- 保活 -->
<uses-permission android:name="android.permission.WAKE_LOCK" />
<uses-permission android:name="android.permission.REQUEST_IGNORE_BATTERY_OPTIMIZATIONS" />
```

### 保活引导（必须在 App 内实现）

国内厂商 ROM 的省电策略会杀掉任何后台服务。App 需要提供「一键体检」页面，逐项引导用户：

1. 通知权限
2. 自启动 / 后台运行
3. 电池优化白名单
4. 锁定最近任务卡片
5. 无障碍服务（如需自动上行）

### 前端服务约束

- Android 14+：必须 `startForeground(id, notification, FOREGROUND_SERVICE_TYPE_DATA_SYNC)`
- Android 15+：`dataSync` 前台服务有 **6 小时/24 小时**上限，超时回调 `onTimeout()`，必须 `stopSelf()`
- Android 16+：后台任务需遵守运行时配额

## 四、端到端联调

### 1. 服务端健康检查

```bash
curl https://clip.example.com/healthz
# {"status":"ok","online":0,"version":"1.0.0","time":...}
```

### 2. 模拟配对

```bash
curl -X POST https://clip.example.com/api/pair \
  -H "Content-Type: application/json" \
  -d '{"pairCode":"482913","deviceId":"test-01","deviceName":"测试机","platform":"windows"}'
```

### 3. Windows ↔ Android 文本互测

1. Windows 上复制一段文字 → Android 应弹出通知 → 点击「复制」按钮可粘贴；
2. Android 上（分享菜单或无障碍）发送一段文字 → Windows 剪贴板应立即可粘贴；
3. 反复复测同一段内容，确认服务端日志**不会**重复广播（去重生效）。

### 4. 防回环验证（必做）

在 Windows 上复制文本 A，观察服务端日志：

```
内容已同步 from=win-xxx kind=text origin=clipboard delivered=1
```

**不应**出现第二条相同的 `内容已同步` 记录。若出现，说明防回环逻辑失效，需检查 `SyncOrchestrator.OnRemoteClipReceived` 中 `_cache.Add(payload.Hash)` 是否在写剪贴板**之前**执行。

### 5. 离线补推验证

1. 关闭 Android 端（或在飞行模式）；
2. 在 Windows 上复制文本 B；
3. 恢复 Android 网络 → 应立即收到 B。

## 五、故障排查

| 现象 | 可能原因 | 排查方向 |
| --- | --- | --- |
| Windows 显示「未连接」 | 地址错误 / 证书问题 / 未配对 | 看日志目录；`curl /healthz` 是否通 |
| Android 端连不上 | 用了 `http://` | Android 9+ 禁止明文，必须 `https://` |
| 复制内容不触发同步 | 前台应用在排除列表 | 检查设置页「排除的应用」 |
| 同一内容被反复同步 | 防回环失效 | 检查 HashCache 的 Add/Consume 顺序 |
| 服务端重启后要重新配对 | `JWT_SECRET` 未持久化 | 配置 `/etc/clipbridge/env` |
| 截图没同步 | 目录路径不对 / 文件未写完 | 查看日志；确认「监控系统截图目录」已勾选 |
| 上传报 413 | Nginx 与 Go 的大小限制不一致 | 对齐 `client_max_body_size` 与 `max_file_size` |

日志位置：

- Windows：`%APPDATA%\ClipBridge\logs\`
- 服务端：`journalctl -u clipbridge -f`

## 六、开发约定

1. **协议优先**：任何消息格式变更必须先改 `shared/protocol/PROTOCOL.md`，再改实现；
2. **防回环是红线**：任何涉及"写剪贴板"的改动都必须回归验证回环；
3. **新增字段一律可选**：保证旧客户端不会因新字段而解析失败；
4. **敏感信息不入日志**：文本内容只记录长度与哈希前缀，不记全文。
