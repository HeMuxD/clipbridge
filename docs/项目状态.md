## 关键设计决策记录

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 拓扑 | 中心化转发 | 用户已有服务器，实现成本远低于 P2P |
| 图片传输 | HTTP 上传 + WS 传元数据 | 避免大 payload 阻塞长连接 |
| Token 方案 | 自实现 HMAC-SHA256 | 无需引入 JWT 依赖，具备过期与验签能力 |
| 服务端存储 | SQLite | 个人规模零运维，性能绰绰有余 |
| **SQLite 驱动** | **modernc.org/sqlite（纯 Go）** | **不用 mattn/go-sqlite3 是因为后者依赖 CGO，会导致 `CGO_ENABLED=0` 静态编译与交叉编译失败。本项目要走 Docker 和多平台发布，纯 Go 方案显著更省事；代价是 CPU 密集型查询稍慢，但本项目只有简单 INSERT/SELECT，可忽略** |
| Windows 监听 | 消息钩子（非轮询） | 系统事件驱动，CPU 占用近零，零权限 |
| **同步语义** | **只同步"当前这一次"复制/截图** | 用户不关心几分钟前复制过什么；旧的离线积压一次性补推还会连续覆盖剪贴板，属于干扰而非功能。默认 `offline_replay_seconds: 0` |
| **Android 下行** | **静默写入剪贴板（无通知）** | 写剪贴板不受后台限制（AOSP 里 `OP_WRITE_CLIPBOARD` 直接放行），所以"收到即进剪贴板、切过去直接粘贴"完全可行；要用户点通知按钮反而多余 |
| **Android 上行** | **无障碍服务两路互补 + 分享兜底** | 无障碍服务并不在系统的剪贴板读豁免名单里（见 AOSP `clipboardAccessAllowed`），所以必须先试读剪贴板、读不到再按无障碍事件还原；分享菜单是 100% 可靠的兜底 |
| **Android 保活** | **两层：无障碍服务（零通知）+ 后台保护前台服务（默认开启）** | 无障碍服务是零通知的干净持有者，但很多 ROM 会在 App 被划出最近任务后连进程一起掐掉。前台服务加上 `stopWithTask=false`、`START_STICKY`、**AlarmManager 看门狗**（闹钟由系统持有、不随进程消亡）与开机自启，才能做到"划掉后台仍继续同步"。两者都用 `SyncEngine` 引用计数持有连接，谁退出都不会立刻断 |
| **部署形态** | **单镜像（Go + Nginx）** | 一个容器、两条挂载；反代走容器内回环，图片由 Go 进程自己提供，数据卷不必暴露给任何外部进程 |
| 防回环 | 哈希缓存双向比对 | 服务端与客户端各设一道，避免无限循环 |

四项需求：只同步当前操作、Android 改无障碍无感同步、单镜像打包、适配被封端口的部署。

### 1. 只同步"当前这一次"复制/截图

| 位置 | 改动 |
| --- | --- |

| `server/internal/api/server.go` | 补推窗口为 0 时：不入队；设备上线时把残留积压**直接丢弃**并记日志 |
| `clients/windows/src/Services/ClipboardService.cs` | 启动时把剪贴板里已有内容登记为历史，永不上报；顺带修好"手动同步"菜单（原先是个空操作） |

顺带修掉一个真实缺陷：Windows 对一次剪贴板写入常常投递多次 `WM_CLIPBOARDUPDATE`，
原先"命中即移除"会让第二次回调把同一内容重新上报一遍。

### 2. Android 改为无障碍服务无感同步

新增 `ClipboardAccessibilityService`（上行）、`SyncEngine`（连接持有者，引用计数管理）、
`ClipboardWriter`、`HashCache`；`SyncService` 降级为**可选**的前台服务保活（默认不启动）。

- **下行**：收到即静默写入剪贴板（文本直接写；图片存相册 + 以 `content://` URI 写剪贴板），
  **移除了通知栏的「复制」按钮与「收到内容」通知**
- **上行**：先试读系统剪贴板；读不到则用无障碍事件（文本选中 + 复制/剪切点击）还原，
  中文标签用包含匹配、英文用精确匹配（否则 "cut" 会命中 "execute"）
- `MainActivity` 增加无障碍状态检测与开启引导、可选保活开关

> 技术依据：AOSP `ClipboardService.clipboardAccessAllowed` 中，**读**操作的豁免名单是
> 焦点应用 / 默认输入法 / SystemUI / ContentCapture / Autofill，**不含无障碍服务**；
> 而**写**操作 `allowed = true` 无条件放行。所以"静默下行"可行，"静默上行"必须分层兜底。

### 3. 单镜像（Go 二进制 + Nginx）

- `deploy/docker/Dockerfile`：两阶段 —— `golang:1.22-alpine` 编译，`nginx:1.27-alpine` 作运行基础镜像
- 新增 `entrypoint.sh`：渲染 nginx 配置、同时拉起两个进程、统一转发信号
  （只有两个进程，不需要 supervisord/s6 那类进程管理器）
- 新增 `nginx.http.conf.template` / `nginx.https.conf.template`：占位符由 entrypoint 用 sed 填充，
  特意不用 `${}` 写法，免得误伤 nginx 自身的 `$host`、`$http_upgrade` 变量
- 构建上下文改为**仓库根目录**，新增根级 `.dockerignore`（排掉 Android 构建产物、`server/data/` 等）
- 删除被取代的 `deploy/docker/nginx.conf` 与 `server/.dockerignore`

### 4. 端口（家庭宽带 80/443 被封）

- 对外统一 **8443**；`.env` 里 `CLIPBRIDGE_HTTPS_PORT` **一个变量同时控制容器内监听端口与宿主机映射**，避免错配
- 证书目录通过 `CLIPBRIDGE_CERT_DIR` 注入（适配 acme.sh DNS-01，不占用 80 端口），
  容器内固定读 `/certs/{fullchain,privkey}.pem`
- 无证书时**不崩**，降级为仅明文 HTTP 并在日志里说明
- `entrypoint.sh` 增加配置缺失检测，直接提示"Docker 把 config.yaml 建成了目录"这个经典坑
- `deploy/nginx/clipbridge.conf`（非 Docker 方案）同步改为 8443，并改用 acme.sh 说明

### 1. 后台保护：App 被划掉后仍继续同步

原来只有"可选的前台服务"，默认关闭且**没有任何恢复手段**，用户打开后一旦清掉通知
或划掉最近任务就掉线。改成一套有兜底的保活结构：

| 手段 | 作用 |
| --- | --- |
| `android:stopWithTask="false"` | **划出最近任务时服务不被连带销毁**，连接继续保持着 |
| `START_STICKY` | 被系统回收后请求重建 |
| 新增 `KeepAlive` + `KeepAliveReceiver`（`AlarmManager`，5 分钟自检） | 闹钟由系统持有、**不随进程消亡**，是进程已被杀之后唯一还能把服务叫回来的东西；`onTaskRemoved` / `onDestroy` 也会预约一次很快的自检 |
| 新增 `BootReceiver` | 开机自启，否则手机重启后就一直离线 |
| `KeepAlive.requestIgnoreBatteryOptimizations` / `openAutoStartSettings` | App 内引导加入电池优化白名单、以及逐个尝试厂商自启动设置页（小米 / 华为 / 荣耀 / OPPO / vivo）。这两项 App 无法代替用户设置 |
| `SyncEngine.ensureConnected()` | 服务还在但连接断了时主动补连 —— 只重新 `acquire()` 不够：引用计数仍大于 0 时不会触发新连接，而指数退避的重连协程已随进程消失 |
| 通知图标换 `ic_notification`（纯白剪影） | 原来用彩色图标，系统会渲染成白方块；文案随连接状态变化 |
| 新增 `Prefs.KEY_BG_PROTECT`（默认 **true**） | 旧的 `keepalive_fgs` 键废弃，使升级安装也会切到开启状态 |

> 做不到的：用户"强行停止"后任何 App 都无法自启（Android 设计）。
> `targetSdk` 保持 34 以规避 Android 15 对 `dataSync` 前台服务的时长限制。

### 2. 诊断面板：定高可滚动 + 2 小时自动淘汰

`List<String>` → `List<DiagEntry>(at, stamp, line)`。界面固定 180dp 高度、内部滚动；
除新增时清理外，UI 层每 30 秒还会主动 `pruneDiag()` —— 否则没有新事件时列表不收缩。
上限 500 条兜底。

### 3. 配对信息持久化

配对码此前从不保存（输入框一直从空串开始），且配对结果用 `apply()` 异步落盘，
进程若在其完成前被杀就一起丢。现在配对码在**配对成功后**写入、启动时回填；
`Prefs.save()` 改用 `commit()` 同步写入。

### 4. 图标与通知图标

自适应图标三层：`ic_launcher_background` + `ic_launcher_foreground` +
`mipmap-anydpi-v26`（方与圆），另补 Android 7.x 的 `mipmap-anydpi` 矢量回退。
沿用蓝色剪贴板基底，中间加"文本行 + 图片框"二合一标记；
所有图形控制在自适应图标安全区圆（半径 33）以内。
删除旧的 `res/drawable/ic_launcher.xml`。

## 修复与验证记录

日期：2026-09-28。用 Go 1.22.12（与 Dockerfile 中的 `golang:1.22` 对齐）完成了真实编译与验证，
过程中发现并修复了 4 个服务端缺陷，其中 2 个是**致命**的——在修掉之前，服务端实际上无法使用。

### 修复的缺陷

| # | 位置 | 问题 | 影响 |
| --- | --- | --- | --- |
| 1 | `internal/auth/auth.go` | `VerifyToken` 用 `fmt.Sscanf(raw, "%s\|%d")` 解析 payload；`%s` 会一直读到空白符，把整个 `设备ID\|时间戳` 吞掉，随后的 `\|` 匹配不上 | **致命**：所有自己签发的 Token 都验不过，凡带鉴权的接口一律 401。配对能成功，但配完就没法用。已改为按最后一个 `\|` 手工切分并用 `strconv.ParseInt` 解析 |
| 2 | `internal/api/server.go` | 日志中间件的 `statusWriter` 包装了 `ResponseWriter`，而结构体包装只会提升接口自身的三个方法，`http.Hijacker` 丢失 | **致命**：`websocket.Upgrader` 断言 Hijack 失败，所有 `/ws/v1` 升级返回 500，整个 WebSocket 链路不通。已显式转发 `Hijack` 与 `Flush` |
| 3 | `internal/api/server.go` | `/api/history` 与离线补推拼图片下载地址时漏掉扩展名（磁盘文件名是 `fileId + ext`） | 图片 URL 404，历史记录与离线补推里的图片都取不到。已统一走 `downloadURL(fileID, mime)`，mime 缺失时回退到磁盘实际文件名 |
| 4 | `internal/api/server.go` | 服务端自身没有 `/f/` 静态服务，图片下载完全依赖前置 Nginx 直接读磁盘 | 容器化时数据卷由 Docker 管理，宿主机 Nginx 根本看不到文件；单进程部署也无法取图。已新增内置 `/f/` 处理器，用白名单正则限定 `32 位小写十六进制 + 图片扩展名`，杜绝目录穿越与目录列举 |

端到端覆盖的链路：

1. 配网两台设备 → 各自建立 WebSocket 长连接（验证 Bearer Token 鉴权）
2. 文本上行：A 发送 → 收到 `ack ok` → B 收到广播，且 `srcDevice/srcName` 由服务端正确回填
3. 重复内容再发一次 → 返回错误码 `2003`（去重生效，防回环第一道防线）
4. 上传图片 → 返回的 URL 带扩展名
5. 断开 B → A 发送图片 → 服务端日志 `delivered=0`，内容进入离线队列
6. B 重新上线 → 收到补推内容（`补推离线内容 count=1`），URL 带扩展名
7. 按该 URL 下载 → HTTP 200，字节数与上传内容一致
8. 查询 `/api/history` → 图片条目 URL 带扩展名

### 部署相关改动

- `deploy/docker/` 补齐了原先缺失的 `config.yaml`（compose 挂载的文件若不存在，Docker 会建出**同名目录**，容器随即启动失败），新增 `.env.example`
- 新增 `server/.dockerignore`，避免把运行时产生的 `data/`（SQLite 库与用户图片）固化进镜像层
- 补上 `server/go.sum`。以前没有它，Dockerfile 里的 `COPY go.mod go.sum*` 在 glog 匹配不到文件时会直接失败
- Dockerfile 支持 `GOPROXY` 构建参数（默认走 `goproxy.cn`），并注明 `go.sum` 必须提交
- `deploy/nginx/clipbridge.conf` 的 `/f/` 默认改为反向代理到后端（Nginx 不必再读数据卷）；
  原 `alias` 直读磁盘的方案保留为注释，供 systemd + 固定路径部署时启用
